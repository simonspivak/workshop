# Шлюз KIE для курса «ИИ-старт»

Через этот шлюз платформа курса (и ведущий на демо) генерирует текст, картинки, видео, голос и музыку моделями kie.ai.
Ключ kie никогда не уходит в браузер: он хранится в n8n, а шлюз принимает только запросы с секретным заголовком.

- Где: n8n → workflow **«ИИ-старт: шлюз KIE для курса»**.
- Как вызвать: `POST` на production-адрес вебхука из этого workflow, заголовок `x-iistart-key: <секрет>`, тело — JSON.
- Секрет и адрес — **только** в n8n (узел `Build KIE Request`) и в переменных окружения платформы (`KIE_GATEWAY_URL`, `KIE_GATEWAY_KEY`). В репозиторий их не класть: он публичный.
- Сейчас workflow **не опубликован**: production-адрес начнёт отвечать, когда его опубликуют в n8n. Тестовые запуски идут вручную.
- Запросы без правильного заголовка отсекаются ещё на вебхуке (`onlyRunIf`) и не создают запусков.

## Как это работает

1. Платформа отправляет `action` и параметры.
2. Шлюз проверяет секрет и белый список моделей, собирает тело запроса под нужную модель и отправляет его в kie.
3. Текст возвращается сразу. Для картинок, видео, голоса и музыки возвращается `taskId`.
4. Платформа спрашивает `{"action":"status","taskId":"…"}` по расписанию (`lib/platform/job-poll.ts`), пока не придёт `done: true`. С 16 ноября kie может сам сообщить платформе, что задача закончилась (раздел «Обратный вызов kie»); тогда платформа спрашивает статус сразу, а опрос остаётся запасным путём.
5. Ответы приводятся к одному виду: `{ ok, state, done, urls[], credits, error }`.

Ссылки kie временные (около 14 дней): после `success` платформа сразу копирует файл в своё хранилище.

## Ошибки шлюза и повторы (16 ноября 2026)

Аудит 8 ноября (`docs/platform/audit-2026-11-08.md`, № 6, 8, 20, 22): шлюз отдавал любой отказ kie как HTTP 502, и платформа повторяла даже «нет кредитов». Теперь платформа (`lib/server/gateway.ts`, `failureKind`) различает отказы по коду kie.

### Что платформа ждёт от шлюза при отказе

HTTP-статус ответа остаётся **502** (как сейчас в «Normalize Response»). Код kie — в теле, отдельным полем:

```json
{ "ok": false, "httpStatus": 502, "error": "<msg от kie>", "kieCode": 402 }
```

- `kieCode` — поле `code` из ответа kie (число; строка из цифр тоже принимается). Нужно **на всех маршрутах**: `create`, `status` и `text`. Сейчас его нет на `text` — платформа там узнаёт только нехватку кредитов и неверный ключ по тексту `error`.
- Нет `kieCode` — платформа работает как раньше, по `httpStatus` и тексту `error`.
- Собственные отказы шлюза («Build KIE Request»: 400 неверный запрос, 401 неверный ключ) остаются HTTP 400/401 без `kieCode`.

Создание задачи: если n8n не дождался kie (KIE POST, 40 с), ответ должен говорить, что задача у kie, возможно, создана:

```json
{ "ok": false, "httpStatus": 504, "error": "kie timeout: <message>", "uncertain": true }
```

Шлюз выдаёт этот ответ веткой On Error узла «KIE POST», когда маршрут — `create`. Тогда платформа не повторяет запрос и не возвращает звёзды сразу.

Пока ветки On Error нет, n8n сам отвечает HTTP 500 `{"code":0,"message":"Error in workflow"}`, без поля `ok`. Такой ответ при создании задачи платформа считает `uncertain`, если ждала его не меньше 30 с. Быстрый ответ того же вида повторяется как временный сбой.

### Как платформа поступает с отказом

Код берётся из `kieCode` (если он 400–599), иначе из HTTP-статуса.

| Отказ | Повторы | Что видит ученик |
|---|---|---|
| 429 (лимит kie: ~20 новых генераций за 10 с на аккаунт) | паузы ~10, 12, 14 с, у каждого запроса разброс ±30 %; в бюджете 45 с (создание) или 42 с (текст) это 3 попытки | при неудаче — `gateway_error` («перегружен… попробуй ещё раз») |
| 5xx, «Resources are tight», сеть | как раньше: паузы 1,5/3/5/8 с; текст идёт по цепочке Kimi → Kimi → Haiku → Kimi → GPT | `gateway_error` |
| 401, 402, 403, 404, 455, 505, или в тексте ошибки «insufficient», «not enough credits», «unauthorized», «invalid api key» | **нет**, запасные модели тоже не пробуются | `gateway_unavailable`: «Генерации временно недоступны: сообщите ведущему. Звёзды вернулись.» |
| прочие 4xx (400, 422 …) | **нет** | `gateway_rejected`: «Сервис генерации отклонил этот запрос…» |
| таймаут, `uncertain` | нет: kie мог списать | задача ждёт; через 90 с без `taskId` звёзды возвращаются (`gateway_lost`) |

Коды kie для нехватки кредитов (402) и техработ (455) взяты по памяти о документации kie. Живым запросом их не проверяли: docs.kie.ai из песочницы аудита недоступен. Если kie отвечает на нехватку кредитов другим кодом из диапазона 4xx, повторов всё равно не будет. Ученик тогда увидит `gateway_rejected`, а не `gateway_unavailable`.

Постоянный отказ пишется в логи Vercel: `generate: gateway rejected { kieCode, httpStatus, error }`.

### `jobId` при создании задачи

В запросе на создание задачи (`image` … `music`) платформа передаёт `jobId` — id задачи платформы. Он одинаковый во всех повторах одной задачи. Шлюз может пока не обращать на него внимания, но **не должен отклонять** запрос с этим полем.

Предложение для шлюза (аудит № 20): после успешного создания записывать `{jobId, taskId}` в Data Table n8n. Тогда шлюз сможет:

- на повтор с тем же `jobId` возвращать уже созданный `taskId`, а не создавать вторую задачу;
- отвечать на будущее действие `lookup`.

### Платформа: повтор после обрыва ответа (аудит № 22)

- Функция `/api/generate` может оборваться: Vercel тогда отвечает 5xx без JSON. Браузер в этом случае сохраняет ключ идемпотентности. Повторный клик находит ту же задачу и второй раз не списывает. Ученик видит `request_lost`.
- Повтор с ключом неудавшейся задачи сразу возвращает ошибку этой задачи. Следующий клик создаёт новую задачу.
- Текст, чей запрос оборвался (в очереди больше 65 с), при повторе сразу получает возврат звёзд (`gateway_lost`).
- Бюджет текста — 42 с вместо 50: n8n всё равно обрывает kie на 40 с, а остаток функции нужен на возврат звёзд.

## Обратный вызов kie: `callbackUrl` (16 ноября 2026)

**Зачем.** Сейчас результат забирается, только пока ученик держит вкладку открытой: готовое видео ждёт, пока он вернётся. Каждая проверка статуса — платный запуск n8n, на одно видео их ~9. С обратным вызовом kie сам сообщает платформе, что задача закончилась. Платформа сразу спрашивает статус (один запуск n8n) и копирует файл, даже если вкладок нет.

### Что присылает платформа

В запросе на создание задачи (`image`, `image_edit`, `video`, `motion`, `lipsync`, `voice`, `music`) рядом с `jobId` появляется необязательное поле `callbackUrl`:

```json
{ "action": "video", "prompt": "…", "jobId": "<uuid задачи платформы>",
  "callbackUrl": "<APP_URL>/api/jobs/callback?job=<тот же uuid>&sig=<64 hex-знака>" }
```

- `<APP_URL>` — переменная `APP_URL` платформы (адрес сайта на Vercel). Адрес собирается при каждом запросе из настроек, в коде его нет.
- Поля **нет**: для `text`; в mock-режиме; когда `APP_URL` не задан или указывает на `localhost`; у задач ботов (`lib/server/bot/card.ts` не передаёт `jobId`). Тогда всё работает как раньше, только опросом.
- `sig` — подпись `job` ключом сервера платформы. Подпись привязана к одной задаче. По адресу можно только попросить платформу проверить эту задачу. Подробности — `docs/platform/spec.md` §8.

### Что сделать в n8n (Сеня)

Узел с ключом шлюза (**«Build KIE Request»**) не трогаем. Всё делается в **«Доработке запроса»**: этот узел и так меняет готовое тело запроса к kie, и ключ ему не нужен.

1. **Проверить, что шлюз не отклоняет новое поле.** Отправить тестовый запрос `image` с лишним полем `callbackUrl`. По копии кода «Build KIE Request» от 5 ноября узел читает только известные поля и про лишние молчит, но проверять надо на живом workflow. Если шлюз отклоняет запрос, напишите: поле выключим в коде платформы. Убрать `APP_URL` для этого нельзя, на нём вебхуки Telegram.
2. **Передать адрес kie.** В «Доработке запроса», в ветке `out.route === 'create'`, перед `return [{ json: out }]`:

   ```js
   const cb = String(body.callbackUrl ?? '');
   // только адрес нашей платформы: https и путь /api/jobs/callback с job и sig
   if (out.route === 'create' && /^https:\/\/[^/?#]+\/api\/jobs\/callback\?job=[0-9a-f-]{36}&sig=[0-9a-f]{64}$/.test(cb)) {
     out.payload.callBackUrl = cb;
   }
   ```

   `body` в узле уже есть (`$('Receive Request').first().json.body`). У kie поле называется **`callBackUrl`** (заглавная `B`) и стоит **на верхнем уровне** тела `POST /api/v1/jobs/createTask`, рядом с `model` и `input`, а не внутри `input`. Так во всех сохранённых страницах документации моделей шлюза (список ниже).
3. **Можно и так:** не передавать адрес в kie, а оставить поле без внимания. Тогда ничего не меняется: опрос работает, как раньше.
4. **Проверить вживую одной дешёвой задачей** (картинка Flux, 1,6 кредита). В журнале Vercel должен появиться `POST /api/jobs/callback` с ответом 200. Задача станет `done` без открытой вкладки. Если вызова нет — смотрите раздел «Что не проверено».
5. Ответ kie на сам вызов шлюз не обрабатывает: kie зовёт платформу напрямую, n8n в этом не участвует и запусков не тратит.

Статус задачи по-прежнему спрашивается через шлюз (`action: "status"`). Ссылки из тела вызова kie платформа не использует.

### Какие модели шлюза принимают `callBackUrl` (по сохранённой документации kie, 1 ноября 2026)

| action | Модель | `callBackUrl` в документации |
|---|---|---|
| `image` | `nano-banana-2-1`, `flux-3/klein-text-to-image` | есть, необязательное, верхний уровень |
| `image` | `nano-banana-pro` | **неизвестно**: страницы этой модели среди сохранённых нет |
| `image_edit` | `nano-banana-2-1`, `flux-3/klein-edit-image` | есть, необязательное |
| `image_edit` | `nano-banana-pro` | **неизвестно** |
| `video` | `bytedance/seedance-2-mini`, `bytedance/seedance-2-5`, `wan/3-0-video`, `wan/3-0-video-prime`, `kling-4.0/reference-to-video` | есть, необязательное |
| `motion` | `kling-2.6/motion-control`, `wan/2-2-animate-move` | есть, необязательное (у `kling-3.0/motion-control`, которого нет в шлюзе, — обязательное) |
| `lipsync` | `kling/ai-avatar-standard`, `infinitalk/from-audio` | есть, необязательное |
| `voice` | `google/gemini-3-8-flash-tts` | есть, необязательное |
| `music` | `ai-music-api/generate` (Suno) | есть, необязательное. Вызовов может быть до трёх: `callbackType` `text`, `first`, `complete`, гарантирован только `complete` |
| `text` | все | нет (синхронный ответ, обратный вызов не нужен) |

Что сказано в документации kie о самом вызове:

- `POST`, JSON. Для моделей Market тело — `{ code, msg, data: { taskId, model, state: "success" | "fail", resultJson, failCode, failMsg, param, … } }`, где `code` 200 — успех, 501 — неудача. У Suno — `{ code, msg, data: { callbackType, task_id, data: [...] } }`.
- В `data.param` kie возвращает параметры создания задачи вместе с `callBackUrl`.
- Ответить нужно за 15 секунд. После трёх неудачных попыток kie перестаёт звать. Это написано на странице вызовов Suno, для остальных моделей сроков и повторов в сохранённых страницах нет.
- Есть необязательная подпись вызова: заголовки `X-Webhook-Timestamp` и `X-Webhook-Signature` = base64(HMAC-SHA256(`taskId + "." + timestamp`, webhookHmacKey)). Ключ включается в настройках kie. Платформа её **не проверяет**: тело вызова ей не нужно, а для проверки понадобилась бы новая переменная окружения с ключом kie. Можно добавить позже.

### Как отвечает платформа

- Неверная или пустая подпись — `404 {"error":"not_found"}`. База и шлюз не трогаются.
- Верная подпись — сразу `200 {"ok":true}`, до любой работы. В ответе нет данных задачи. Проверка статуса и копирование идут в `after()` (срок 55 с, `maxDuration` 60).
- Задача `submitted` — один внеочередной вопрос шлюзу о статусе, без ожидания расписания опроса. Если готово — копирование файла, если `fail` — возврат звёзд. Правила те же, что у опроса. Если kie ещё «генерирует» (`text`/`first` у Suno), задача ждёт следующего вызова или опроса.
- Задача `done`, `failed`, `storing`, `queued`, удалённая — ничего не делаем. Повторные вызовы безвредны.
- `GET` с тем же адресом (проверка доступности) — `200` при верной подписи, без работы.
- Два вызова подряд или вызов одновременно с опросом из вкладки — шлюз спрашивается один раз: замок `claim_job_poll` с паузой 2 с. Файл копируется один раз: замок `begin_job_storing`.

### Что не проверено (до первого настоящего вызова kie)

- Сохраняет ли kie строку запроса (`?job=…&sig=…`) в `callBackUrl`. В примерах документации адреса без query. Если kie её отбрасывает, платформа ответит 404, и задачу доведёт опрос.
- Зовёт ли kie платформу на `fail` для всех моделей. В документации Market сказано «when the task succeeds or fails».
- Успевает ли kie обновить статус (`recordInfo`) к моменту вызова. Если статус ещё не `success`, задача подождёт опроса.
- Как kie ведёт себя для `nano-banana-pro`: страницы документации нет.
- Повторы и тайм-аут вызова для моделей Market (известны только для Suno).

## Картинки в тексте: `images` (16 ноября 2026)

**Зачем.** Домашку проверяет текстовая модель. Картинки (постер, слайды PNG, кадры из галереи) она не видела. Из-за этого ИИ писал «не могу прочитать презентацию», а работы-картинки уходили ведущему. Теперь платформа может приложить к запросу `text` до 6 картинок.

### Что сказано в документации kie (сохранённые страницы, 1 и 5 ноября 2026)

| Модель | Адрес | Картинки на входе | Вид | Лимиты |
|---|---|---|---|---|
| `kimi-k3` | `POST /openai/v1/responses` (OpenAI Responses) | **есть**: «Image input — Mix text and images in a single message» | `input: [{ role: "user", content: [{ type: "input_text", text }, { type: "input_image", image_url }] }]`; `image_url` — «A publicly reachable URL, or a `data:image/{format};base64,{data}` string. The link must be directly downloadable, otherwise the request returns 400»; «Images are only allowed on `user` messages»; «Common formats such as PNG and JPEG are supported» | размер и число картинок не документированы |
| `gpt-6-luna` | `POST /codex/v1/responses` (OpenAI Responses) | **есть**: «Multimodal Input — Supports mixed text, image, and file inputs in a single message» | content parts `{"type":"input_image","image_url":"<URL or data:image/...;base64,...>"}` (и `input_file` с `file_url`) | не документированы |
| `claude-haiku-5-5` (и `claude-sonnet-5-5`) | `POST /claude/v1/messages` | **не документировано**: у `content` — `string` или «Structured content blocks» (`additionalProperties: true`) без описания блоков; примеров с картинкой нет | — | — |

Ответ с картинками — тот же: у Responses `output[].content[]` с `output_text`, `usage.input_tokens` («including the prompt, instructions, history, images…»), `credits_consumed`. Цены картинки в токенах или кредитах в документации нет. Отказ Kimi при недоступной ссылке — `{"error": {"type": "server_error", "message": "Cannot download image [image-url] ..."}}`.

Поэтому платформа (`lib/server/gateway.ts`, `VISION_TEXT_MODELS`) шлёт картинки только в `kimi-k3` и `gpt-6-luna`: с картинками цепочка — Kimi → Kimi → Kimi → GPT 6 Luna (Haiku пропускается). Без картинок цепочка прежняя.

### Что присылает платформа

```json
{ "action": "text", "model": "kimi-k3", "prompt": "…", "system": "…", "maxTokens": 1200,
  "images": ["https://<STORAGE_HOST>/storage/v1/object/sign/media/<путь>?token=…", "…"] }
```

- Поле `images` есть, **только когда картинки есть** (сейчас — только проверка домашки). Чат, боты и проверка без картинок шлют запрос как раньше, без поля.
- Ссылки — подписанные ссылки Supabase Storage на бакет `media`, свежие, живут час. Только `https`, без повторов, не больше 6.
- Порядок важен: в промпте написано «картинка 1 — файл работы, картинка 2 — результат из галереи…». Части `input_image` должны идти в том же порядке.

### Что сделать в n8n (Сеня)

«Build KIE Request» (узел с ключом) не трогаем. Он читает только известные поля, `images` для `text` молча пропускает: картинки до модели не доходят, но и ошибки нет. Всё делается в **«Доработке запроса»**.

`<STORAGE_HOST>` — хост Supabase платформы (как в `NEXT_PUBLIC_SUPABASE_URL`, без `https://`). Вписать его в узел n8n. В репозиторий хост не класть.

**1.** В начало узла, после строки `const body = …`, добавить:

```js
// 4) Картинки для текста (проверка домашки, 16 ноября 2026). body.images — до 6 подписанных ссылок
//    на Storage платформы. Поля нет — ничего не меняется.
const STORAGE_HOST = '<STORAGE_HOST>';
const IMAGE_PREFIX = `https://${STORAGE_HOST}/storage/v1/object/sign/media/`;
// Картинки на входе есть в документации kie только у этих моделей (OpenAI Responses)
const VISION_TEXT = ['kimi-k3', 'gpt-6-luna'];
// Claude Messages: блоки картинок у kie не документированы. Включать после живой проверки.
const CLAUDE_IMAGES = false;
const imagesFail = (error) => [{ json: { ok: false, httpStatus: 400, error } }];

/** Проверить body.images: { list } или { error } (текст ошибки начинается с «images:»). */
function textImages(model) {
  if (body.images === undefined) return { list: [] };
  const list = Array.isArray(body.images) ? body.images : null;
  if (!list || list.length > 6) return { error: 'images: up to 6 links expected' };
  if (list.some((u) => typeof u !== 'string' || u.length > 2048 || !u.startsWith(IMAGE_PREFIX))) {
    return { error: 'images: only https links to platform storage' };
  }
  const claude = String(model).startsWith('claude-');
  if (list.length && !VISION_TEXT.includes(model) && !(claude && CLAUDE_IMAGES)) {
    return { error: `images: model ${model} does not take images` };
  }
  return { list };
}

/** Переписать готовое тело запроса: текст + картинки по порядку. Тело уже собрано Build (или веткой Kimi). */
function withImages(payload, list) {
  if (!list.length) return payload;
  if (Array.isArray(payload.messages)) {
    // Claude Messages (только при CLAUDE_IMAGES = true)
    const text = String(payload.messages[0]?.content ?? '');
    payload.messages = [{ role: 'user', content: [
      { type: 'text', text },
      ...list.map((url) => ({ type: 'image', source: { type: 'url', url } })),
    ] }];
  } else {
    // OpenAI Responses (kimi-k3, gpt-6-luna): input-строка → одно сообщение user с частями
    const text = String(payload.input ?? '');
    payload.input = [{ role: 'user', content: [
      { type: 'input_text', text },
      ...list.map((url) => ({ type: 'input_image', image_url: url })),
    ] }];
  }
  return payload;
}
```

**2.** В ветке Kimi K3 (`EXTRA_TEXT`), вместо последней строки `return [{ json: { ok: true, route: 'text', … payload } }];`:

```js
  const imgs = textImages(body.model);
  if (imgs.error) return imagesFail(imgs.error);
  return [{ json: { ok: true, route: 'text', method: 'POST', url: EXTRA_TEXT[body.model], payload: withImages(payload, imgs.list) } }];
```

**3.** Сразу **после** блока `if (out.route === 'text' && body.system) { … }` (он пересобирает `messages` и `instructions`, поэтому картинки — после него):

```js
if (out.route === 'text') {
  const imgs = textImages(out.payload.model);
  if (imgs.error) return imagesFail(imgs.error);
  withImages(out.payload, imgs.list);
}
```

Проверка ключа не меняется: оба места выполняются, только когда Build уже проверил ключ (ветка Kimi — после ошибки «model … is not allowed», шаг 3 — при `out.ok === true`).

### Что платформа ждёт в ответ

- Ответ **тот же**, что без картинок: `{ ok: true, action: "text", model, text, credits, usage }`. «Normalize Response» менять не нужно: Responses отдаёт `output[].content[]` с `output_text`, Claude — `content[]`.
- Отказ — как сейчас: `{ ok: false, httpStatus, error }`. Если в `error` есть слово `image` (свой отказ «images: …» или «Cannot download image» от kie), платформа не повторяет запрос другой моделью. Она проверяет работу **без картинок**, как раньше: по тексту или, если сдана только картинка, — ведущим. Сдача из-за картинок не падает.
- Модель отвечает полем `images_seen` в JSON оценки. Пока шаги 1–3 не сделаны, шлюз картинки молча не передаёт. Ожидается, что модель тогда ответит `images_seen: 0`, и платформа оценит работу как раньше. Это поведение модели, живым запросом не проверено. Надёжнее сначала сделать шаги 1–3, потом выкатывать платформу. Выключатель на платформе — `AI_SEES_IMAGES` в `lib/platform/homework-types.ts`.

### Что не проверено (до первого настоящего вызова)

- Скачивает ли kie картинку по подписанной ссылке Supabase (ссылка с `?token=…`, `Content-Type` из бакета). Документация требует «publicly reachable», «directly downloadable». Подписанная ссылка публична на час.
- Реальная цена картинки: в документации нет ни токенов, ни кредитов за картинку. Смотреть `usage.input_tokens` и `credits_consumed` в первых ответах.
- Предел размера и числа картинок у kie: не документирован. Платформа шлёт не больше 6, загруженный файл — не больше 20 МБ.
- Видит ли Haiku картинки через `/claude/v1/messages`. Поэтому `CLAUDE_IMAGES = false`, а платформа Claude картинки не шлёт.

## Музыка: длина и голос (23 ноября 2026)

**Зачем.** Платформа не передавала длину, и шлюз ставил 30 с: каждый трек был 30 с, а ученики монтируют ролики на 60–90 с — песня со словами обрывалась на припеве. Голос певца выбрать было нельзя.

### Что сказано в документации kie (Suno)

- В custom-режиме есть необязательные `duration` — желаемая длина трека в секундах, 10–360, и `vocal_gender` — `m` или `f`.
- Оба поля работают **только в custom-режиме**. «Build KIE Request» включает его, когда есть `lyrics` или `instrumental: true`. Простой режим («опиши песню», Suno сам пишет слова) их не принимает.
- 23 ноября kie брал 12 кредитов за генерацию независимо от длины и возвращал 2 трека.

### Что присылает платформа

```json
{ "action": "music", "model": "ai-music-api/generate", "prompt": "pop, warm, acoustic guitar",
  "lyrics": "[Verse]\n…", "title": "…", "duration": 90, "vocalGender": "f", "jobId": "…" }
```

- `duration` — 30, 60, 90 или 120 (схема `/api/generate` принимает любое целое 10–120). Только с `lyrics` или с `instrumental: true`.
- `vocalGender` — `m` или `f`, только с `lyrics`. «Любой» — поля нет. С `instrumental: true` не приходит никогда, и `lyrics` тогда тоже нет.
- Простой режим (без `lyrics` и без `instrumental`) — ни `duration`, ни `vocalGender`.

### Что сделать в n8n (Сеня)

«Build KIE Request» (узел с ключом) не трогаем: он режет `duration` до 60 с (`Math.min(… || 30, 60)`) и `vocalGender` не знает. Всё делается в **«Доработке запроса»**: узел стоит после Build, видит исходное тело (`body`) и может переписать `out.payload.input`.

Добавить перед последней строкой узла `return [{ json: out }];`:

```js
// 5) Музыка: длина до 2 минут и голос певца (платформа, 23 ноября 2026).
//    Suno принимает duration и vocal_gender только в custom_mode (свой текст или без вокала).
//    «Build KIE Request» режет duration до 60 с и голос не знает — правим здесь.
const music = out.payload && out.payload.input;
if (out.route === 'create' && out.action === 'music' && music && typeof music === 'object' && music.custom_mode === true) {
  const seconds = Math.round(Number(body.duration));
  if (Number.isFinite(seconds) && seconds > 0) music.duration = Math.max(10, Math.min(seconds, 120));
  if (music.instrumental !== true && (body.vocalGender === 'm' || body.vocalGender === 'f')) music.vocal_gender = body.vocalGender;
  else delete music.vocal_gender;
}
```

- Работает только для `route: 'create'`, `action: 'music'` и `custom_mode: true`. Простой режим не трогается.
- `duration` — целое 10–120 (kie допускает до 360, платформа больше 120 не шлёт). Нет поля — остаётся значение Build (30 с).
- `vocal_gender` — только `m` или `f` и только у песни с вокалом. Прочие значения и `instrumental: true` — поля нет.
- Проверено без сети: сниппет вставлен в копию «Доработки запроса» и прогнан на копии музыкальной ветки Build — 120 с без вокала, 90 с с `f`, 500 → 120 и `x` → без голоса, простой режим без изменений.

### Что не проверено (до первого настоящего вызова)

- Насколько точно Suno V6 Mini держит `duration` (это «желаемая» длина) и меняется ли цена за трек 2 минуты. Смотреть длину треков и `credits` в первых ответах.
- Как `vocal_gender` слышен на русском тексте.
- Время генерации трека 2 минуты: таймауты платформы для музыки прежние (§ «Ошибки шлюза и повторы»).

- Для GPT передаёт `instructions` (иначе kie подставляет свой длинный промпт).
- Музыка без вокала идёт в `custom_mode`: в простом режиме Suno игнорирует `instrumental` и всё равно поёт.

## Видео с персонажем: одна семья моделей — Seedance

Решение от 1 ноября 2026: всё видео с персонажем делаем на Seedance. У Mini и 2.5 одинаковые поля, один стиль промптов и один режим референсов, поэтому ученики учат один способ работы.

| Кому | Модель | 5 с, 480p | Зачем |
|---|---|---|---|
| Ученики (по умолчанию) | `bytedance/seedance-2-mini` | 19 кр (25★), 1–1,5 мин | Оживить кадр или снять новую сцену по листу персонажа |
| Ведущий: демо, финал микродрамы | `bytedance/seedance-2-5` | 140 кр, ~2,7 мин | Лучшее качество; `lastFrame: true` отдаёт последний кадр, с него начинается следующая сцена |

Как держать персонажа:

1. Лист персонажа (4 ракурса и 3 эмоции) делаем один раз в `image_edit`.
2. Видео запускаем с `reference: true` и листом в `images[]`. В промпте пишем «персонаж с референса… сохрани его внешность».
3. Если кадр уже готов и нужен точно он, — без `reference`: картинка идёт первым кадром.
4. Для сцен подряд (микродрама): Seedance 2.5 с `lastFrame: true`, следующая сцена берёт этот кадр первым кадром.

**Речь в кадре.** Seedance Mini по-русски говорит плохо: 3 теста из 3 неразборчивые, аудио-референс не помогает. Поэтому в видео герои играют без слов (`audio: false` или только шумы), а реплики озвучиваем отдельно (`voice`) и накладываем при монтаже.

Перенос движения (`motion`) и говорящая голова (`lipsync`) остаются на Kling: они проверены, а Seedance для этих задач не тестировали. Wan 3.0 и Kling 4.0 остаются в белом списке как запасные.
