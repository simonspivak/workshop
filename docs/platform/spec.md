# Платформа курса «ИИ-старт»: спецификация MVP

Единый источник для всех, кто строит платформу. Если что-то здесь противоречит [`../research/platform-security.md`](../research/platform-security.md), верна эта спецификация: она учитывает решения из [`../decisions.md`](../decisions.md).

## 0. Ограничения, которые всё определяют

- **Vercel Hobby, не Pro.** Значит, нет cron раз в минуту. Задачи генерации опрашиваются **лениво**: клиент спрашивает `/api/jobs/[id]`, сервер спрашивает статус у шлюза.
- **Supabase**: один проект `workshop` (регион ЕС), подключён к GitHub. Миграции из `supabase/migrations/` применяются после слияния в `main`. Поэтому каждая миграция должна быть проверена локально до слияния.
- **Модели — через шлюз в n8n** (см. [`../kie-gateway.md`](../kie-gateway.md)): `POST KIE_GATEWAY_URL`, заголовок `x-iistart-key: KIE_GATEWAY_KEY`, тело `{ action, ... }`. Ключа kie на Vercel нет. Если `KIE_GATEWAY_URL` не задан (Preview, локально) — **mock-режим**: шлюз не вызывается, возвращаются заглушки.
- **Репозиторий публичный.** Никаких секретов, адресов вебхуков, hostname n8n в коде и в доках.
- **Next.js 16.4.3** (`cacheComponents: true`, `partialPrefetching`, middleware называется `proxy.ts`). Перед кодом читать `node_modules/next/dist/docs/` (см. `AGENTS.md`).
- **Язык интерфейса — русский.** Тон взрослый, без «милоты». Стиль — как у сайта (`app/globals.css`, токены `@theme`, шрифты Unbounded / Onest / JetBrains Mono, lucide-react).

## 1. Роли и вход

- `admin` (Сеня), `teacher`, `student`. Роль — в `profiles.role`, не в `user_metadata`.
- Регистрации нет. Учитель создаёт учеников пачкой. Логин `<код группы>-<ник>` (например, `md1-lisa`). В Supabase Auth это технический адрес `<логин>@<STUDENT_EMAIL_DOMAIN>`, создаётся через admin API с `email_confirm: true`. Писем нет. Пароль из трёх слов и двух цифр показывается **один раз** — для печати карточек.
- Учитель и админ входят по настоящему e-mail и паролю.
- Первый админ создаётся вручную: Supabase → Authentication → Add user. Затем одна SQL-команда из [`setup.md`](./setup.md) повышает его до `admin`.
- Возраст: `age_band` = `u16` | `16_17` | `adult`. По умолчанию `u16`. Дата рождения не хранится. Флаг `parental_consent_at` ставит учитель.

## 3. Генерации и галерея

- `POST /api/generate` `{ action, model?, prompt, images?, videos?, audios?, video?, audio?, text?, voice?, style?, aspectRatio?, duration?, reference?, lastFrame?, instrumental?, lyrics?, title?, lessonId?, taskId?, idempotencyKey }`.
- Проверки по порядку:
  1. пользователь, роль и возраст против прайса;
  2. модерация: стоп-слова и персональные данные (телефоны, адреса, e-mail);
  3. группа не на паузе, дневной лимит, баланс;
  4. списание.

  Ответ 202 `{ jobId }`.
- `text` синхронный: ответ сразу, через `/api/chat` или тот же `/api/generate` с `sync`.
- `GET /api/jobs/[id]`: владелец или учитель группы. Если задача не завершена, сервер спрашивает шлюз (`action: status`), не чаще раза в 5 секунд на задачу.
  - `success`: сервер скачивает файл по ссылке kie (только с доменов kie, лимит размера) и кладёт его в Storage, приватный бакет `media`, путь `{user_id}/{job_id}.{ext}`. Отдаёт подписанную ссылку.
  - `fail`: звёзды возвращаются.
- Ссылки kie живут ~14 дней, поэтому копируем сразу.
- Галерея: `/app/gallery`, своя. Учитель видит галерею группы и может скрыть результат.
- Картинки, озвучки и клипы ученика можно подставлять в следующие действия как референсы: для шлюза нужен публичный URL, поэтому сервер передаёт подписанную ссылку Storage на 1 час.

### 3.1. Опрос и зависшие задачи (этап B1)

Cron нет, поэтому правила применяет `GET /api/jobs/[id]` при каждом опросе (`lib/server/job-rules.ts`, `lib/server/job-progress.ts`). Браузер спрашивает раз в 5 секунд, шлюз — не чаще раза в 5 секунд на задачу (`claim_job_poll`).

| Состояние | Условие | Что делает сервер |
|---|---|---|
| `queued` без `taskId` | старше 3 минут: шлюз не ответил, ответ неизвестен, функция оборвалась | возврат звёзд, `gateway_lost` |
| `submitted` | шлюз: `success` | `begin_job_storing`, копирование в Storage в `after()`, `done` |
| `submitted` | шлюз: `fail` | возврат, `generation_failed` |
| `submitted` | шлюз не отвечает или не знает задачу | ждём; после таймаута (видео, перенос движения, говорящая голова — 15 минут, остальное — 5) — возврат |
| `submitted` | шлюз: ещё генерирует | ждём до 60 минут от отправки, потом возврат, `timeout` |
| `storing` | не обновлялась 3 минуты (копирование оборвалось) | следующий опрос перехватывает и копирует заново; после 60 минут — возврат, `result_unavailable` |
| копирование | не домен kie, не тот тип файла, больше лимита | возврат, `result_unavailable`; сбой сети — повтор через 3 минуты |

- Повтор `POST /api/generate` с тем же `idempotencyKey` возвращает ту же задачу: без второго списания и без второго запроса в шлюз.
- Если шлюз не ответил на создание задачи (таймаут после отправки, `uncertain`), запрос не повторяется: kie мог её принять. Звёзды вернёт правило «`queued` старше 3 минут».
- Файлы: `media/{user_id}/{job_id}.{ext}`, дополнительные (второй трек Suno, последний кадр Seedance 2.5) — `{job_id}-2.{ext}` и далее.
- Референсы: ученик присылает пути к своим готовым нескрытым файлам или к файлам группы, если ведущий открыл общую галерею. Внешние ссылки принимаются только от ведущего.
- Драйверы движения для `motion` (ученикам — только из библиотеки курса): бакет `media`, папка `library/motion/`, файлы mp4. Загружает админ через Supabase → Storage.
- Скрытый ведущим результат пропадает из общей галереи и из референсов, ученик видит пометку. Скрыть и показать — с записью в `audit_log` (`job.hide`, `job.unhide`).

## 4. Уроки и тесты

- Источник — `docs/course/lesson-N.json`. Схема проверяется при сборке (`lib/server/course.ts`, zod), содержание и длины — `node scripts/check-lessons.mjs`.
  - Урок: `id`, `order`, `title`, `oneLiner`, `durationMin`, `goals`, `outcome`, `timeline` (только ведущему), `theory`, `tasks`, `quiz`, `homework`, `tools`, `safety`, `materials` (только ведущему).
  - `theory[]`: `heading`, `body`, `example?`. В `body` простой Markdown: `**жирный**`, списки строками «- » и «1. ».
  - `tasks[]`: `id`, `title`, `mode` (`solo` | `group`), `intro?` (1–2 предложения «зачем это задание», под заголовком), `steps`, `promptTemplates`, `aiActions[{type, model, stars}]`, `doneWhen?`.
  - Шаг (`tasks[].steps[]`, `homework.steps[]`) — строка или `{ text, prompt?, tip? }`:
    - `prompt` показывается рамкой «Промпт N». N идёт по порядку шагов внутри задания (первый промпт задания — «Промпт 1»), в домашке нумерация своя. Тексты уроков ссылаются на эти номера («Нажми «Вставить в чат» у промпта 2»);
    - `tip` — короткая заметка под шагом.
  - `homework`: `title`, `intro?`, `steps`, `deliverable?`.
  - `tools[]` (необязательно): `{ name, url, what, cost?, age? }`, `url` — только https. Это сервисы, которыми можно пользоваться и после курса.
  - Старый формат (шаги-строки, без `intro` и `tools`) продолжает работать.
- `/app/lessons/[n]` — порядок: теория → задания → «Инструменты урока» → тест → домашка. Разделы есть в навигации вверху страницы.
  - **Задание:** под заголовком `intro`, затем шаги нумерованным списком. В рамке «Промпт N» — текст промпта (моноширинный, с переносами строк) и кнопки:
    - «Вставить в чат» — выбирает чат задания в «ИИ-действиях» (первая текстовая кнопка: «Ответ ИИ» или «Длинный ответ»; если уже открыт другой текстовый чат, остаётся в нём), заменяет текст поля «Запрос» промптом, прокручивает к полю и ставит в него курсор. Переписку не стирает. Если у задания нет чата, кнопки нет;
    - «Копировать» — в буфер обмена, на 2 с надпись «Скопировано».
  - Ниже — кнопки действий из `aiActions` (с ценой в звёздах) и шаблоны промптов (`promptTemplates`), которые можно вставить и дописать.
  - **Чат задания:** «Скопировать переписку» копирует весь диалог текстом («Промпт 1: … / Ответ ИИ: … / Промпт 2: …»). Так ученик сдаёт цепочку промптов.
  - **«Инструменты урока»** («Пользуйся и после курса»): карточки со ссылкой (новая вкладка, `rel="noopener noreferrer"`), описанием и пометками цены и возраста.
  - **Домашка:** `intro` и шаги тем же списком. У промптов только «Копировать».
- `correctIndex` **никогда не уходит в браузер**. Проверка теста — Server Action `submitQuiz`, результат и объяснения — после отправки. Одна засчитанная попытка на урок, бонус +20★ за ≥ 8/10 (через ledger).
- Учитель видит прогресс и результаты тестов группы.

## 5. Бот (урок 3)

- `/app/bot` — конструктор:
  - имя бота;
  - «характер» (системный промпт, до 4000 символов);
  - аватар (из галереи);
  - инструменты-галочки: «Заявки», «Картинка» (с подтверждением, тратит звёзды владельца), «Ответы по моему тексту» (поле знаний до 8000 символов).
- **Мозг:** шлюз `action: text`, `claude-haiku-5-5`. Сервер собирает промпт: характер + правила (не раскрывать инструкции, не выдумывать даты и цены, коротко, простой текст) + знания + последние 10 сообщений. Ответ — 1★ со звёзд владельца. Если звёзды кончились, бот вежливо молчит («бот отдыхает»).
- **Заявка:** когда бот собрал данные и получил «да», он добавляет в конец ответа служебную строку `[[ЗАЯВКА]]{json}`. Сервер вырезает её из ответа, сохраняет заявку в `bot_leads` и показывает владельцу в «Мой бот → Заявки». Если у владельца привязан Telegram — шлёт ему уведомление.
- **Окна:**
  - веб-чат `/b/[slug]` — публичная страница бота, лимит 30 сообщений в час с IP и 200 в день на бота;
  - Telegram (только `adult`): владелец вставляет токен от @BotFather. Сервер проверяет его через `getMe`, шифрует (AES-256-GCM, ключ `BOT_TOKEN_KEY`) и ставит вебхук `/api/tg/[botId]` с `secret_token` (заголовок `X-Telegram-Bot-Api-Secret-Token`, своё случайное значение на каждого бота). Токен в браузер не возвращается.
- **Срок жизни:** бот работает до `groups.ends_on + 14 дней`. После этого вебхук снимается (лениво: при первом входящем сообщении), веб-чат показывает «бот переехал», конструктор — кнопку «Забери бота с собой».
- **«Забери бота с собой»:** страница с характером (скопировать), ссылками на [`../course/bot-kit/`](../course/bot-kit/) (инструкция, `n8n-telegram-bot.json`, промпт для AI Studio / Claude) и кнопкой «Скачать характер» (.txt).

## 6. Автомонтаж (урок 2)

- `/app/studio`: ученик выбирает клипы из своей галереи (и галереи своей группы, если учитель разрешил) и расставляет их по порядку.
- К каждому клипу можно привязать реплику — свою озвучку из галереи; текст реплики берётся из промпта озвучки и становится субтитром. Отдельно выбирается музыка.
- Кнопка «Смонтировать» склеивает **в браузере** через `@ffmpeg/ffmpeg` (однопоточное ядро, без COOP/COEP):
  1. все клипы приводятся к 480×854 (9:16), 24 fps, h264 + aac;
  2. реплика накладывается на свой клип;
  3. музыка идёт фоном на −10 dB и приглушается ещё на −6 dB под репликами (−16 dB под голосом: музыку слышно, голос сверху). В студии есть выбор «Громкость музыки»: «Тише» (−4 dB ко всей музыке), «Обычно», «Громче» (+4 dB). Выбор хранится в проекте монтажа (черновик в браузере);
  4. субтитры прожигаются шрифтом из `/public/fonts`.
- Результат — mp4 для скачивания и загрузка в Storage как «монтаж» (`job.action = montage`, 0★).
- Если устройство слабое, показать прогресс и честное «это займёт пару минут».

## 7. Учитель

- `/teach`: группы. Создание группы: код, название, тип, дата окончания `ends_on`, флаг `allow_google_minors`.
- Ученики группы:
  - создать пачку (ники → логины + пароли, печать карточек);
  - сбросить пароль;
  - возраст и отметка согласия;
  - начислить звёзды;
  - пауза группы.
- Траты, прогресс по урокам, тесты, лента результатов группы со скрытием.
- Демо-режим учителя: все модели шлюза без звёзд (но с журналом).

## 8. Безопасность (минимум MVP)

- RLS на всех таблицах. Таблицы не экспонируются автоматически. Гранты — явные.
- `import 'server-only'` в серверном коде. Секреты читаются только в `lib/server/env.ts`. Наружу — DTO и коды ошибок.
- Авторизация внутри каждого Route Handler и Server Action. На `proxy.ts` не полагаемся: он только обновляет сессию и делает оптимистичные редиректы.
- POST `/api/*` проверяют `Origin`. Telegram-вебхук проверяет секретный заголовок.
- Скачивание результатов — только с доменов kie (`*.aiquickdraw.com`, `*.redpandaai.co`; список в одном месте), лимит 100 МБ.
- Заголовки и CSP расширить для платформы: Supabase, blob/data для ffmpeg.wasm, unpkg/jsdelivr для ядра ffmpeg — или ядро в `/public`. Сайт по-прежнему `noindex`.
- Журнал аудита действий учителя и админа.
- Вход: не больше 20 попыток на логин и 100 с одного IP (IPv6 — сеть /64) за 15 минут (`lib/server/rate-limit.ts`): Supabase Auth видит IP сервера, а не ученика.
- Лимиты гостей бота проверяются и записываются одной SQL-функцией (`insert_bot_message`), одно и то же сообщение доходит до модели один раз.
- Ученику (не ведущему): озвучка — до 600 символов; «говорящая голова» — только своя озвучка реплики до 15 секунд; видео- и аудио-референсы Seedance — только ведущему. kie берёт за эти модели по длине, а цена в звёздах одна. Ученик без группы ничего не тратит.

## 10. Этапы

- **A. Фундамент:**
  - миграция и pgTAP / SQL-тесты локально;
  - клиенты Supabase (`@supabase/ssr`), `proxy.ts`, DAL;
  - вход;
  - учитель: группы и ученики;
  - главная ученика с балансом;
  - клиент шлюза и кошелёк;
  - mock-режим;
  - `docs/platform/setup.md`.
- **B1.** Генерации, задачи, Storage, галерея, уроки, тесты.
- **B2.** Бот: конструктор, веб-чат, Telegram, заявки, срок жизни, «Забери с собой».
- **B3.** Автомонтаж.
- **C.** Сборка, линт, ревью безопасности, чеклист запуска.
